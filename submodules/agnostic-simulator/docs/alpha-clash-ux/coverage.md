# Coverage matrix and source audit

## Required browser path

Use board controls, card inspection and dedicated choice controls for gameplay. Do not use **Match actions & log / More** to activate actions, submit choices, pass, undo or otherwise advance the game. It is an escape hatch, not the acceptance path. If a needed action is absent from the board, stop that case and record a UI reachability failure; native tests can still establish engine/adapter behavior separately.

Earlier runs that used this escape hatch are retained only as diagnostic evidence. They do **not** establish accepted real-board completion, even if their final board state is correct. This affects the recorded Death and Trugg ability flows, Rizlac recovery, T-Bone response, reveal fallback selection, and any other run whose steps use that panel. Revalidate those cases through board controls after the missing controls are addressed. Do not use the log as a substitute for visible board feedback.

## Input and lifecycle branch audit

The catalog covers `entity-selection`, `option-selection`, `boolean`, `number`, `ordering`, `entity-partition`, and `entity-allocation` emitted by this adapter. `entity-allocation` has distinct damage and prevention semantics: `allowEmpty` is false for prevention; per-recipient caps come from native amounts. `combat-prevention` now reaches shared clash prevention: attack, respond with Archaic Shield, Foretell, send the revealed card, declare two obstructors, then allocate prevention. `destination-reveal` alone covers reveal, not allocation. Local clash prevention now has a native pre-action variant, split/concentrated tests and laptop browser evidence. Shared non-clash allocation now uses Soul Barrier and Erupting Force, with native resolution and three-size browser evidence. Motion/audio acceptance remains open.

Every public submission converter branch is mapped: resolveChoice, playCard/respond, setCard, activateAbility, attachWeapon/detachWeapon, initiateClash, declareObstructors, deployResource, concede, declareMulligan, mulligan, startGame, activatePortal, pass and its resource/counter/obstruct/clash aliases, and endTurn. Undo/undoToTurnStart are separate dispatch paths. Detach and generic pass conversion are not proof of an advertised interaction.

`ready`, `waiting`, `choosing`, and `game-over` are separate UI states. A non-acting seat can still receive a Concede action; do not equate an empty action list with every waiting state. Simultaneous owner ordering explicitly returns an empty waiting view. Spectators must not receive private candidates.

Projection includes hand/deck visibility, face-down cards, source metadata, board zones, counters, stats, attachments, and public logs. Animation plan generation in the server adapter returns null; current visuals derive from board transitions and game UI. Do not claim complete semantic animation coverage from adapter tests.

## Native reveal visibility gap and scoped follow-up

**Current status:** Archaic Shield’s suspended `revealCards` face now reaches both seats through native projection. Its previous expected-failure test is a positive acceptance check. The rest of public reveal support and browser presentation remain incomplete. The original gap evidence below is historical.

**Rule basis:** [publisher How to Play](https://alphaclashtcg.com/how-to-play) still links [Comprehensive Rulebook 8.0](https://alphaclashtcg.com/s/Alpha_Clash_TCG_Comprehensive-Rulebook-80.pdf), checked October 10, 2026. Rule 703.8a requires all players to see a revealed card for the relevant effect scope. Rule 703.8b keeps it in its current zone. Rule 703.8c ends that reveal on relevant shuffle/reorder. Rule 703.8d distinguishes private looking from revealing. Exact text was read from the repository's canonical v8 extraction; the web tool could verify the current PDF link but could not retrieve its redirected PDF.

**Reproduction and evidence:** create `destination-reveal`, use native attack, Archaic Shield response, both passes, Magnate-top/Sonoro-bottom Foretell, then Done through the production adapter. [Structured snapshot](evidence/reveal-projection-audit.json) records all three projections before, during and after. Before: all deck identities hidden. During: Player 2 sees one named deck card and one pending choice; Player 1 sees no named deck cards. The public reveal log names Magnate. After Done: identities hidden again for every view. Spectator also receives no face; spectator display policy is a product decision, separate from the explicit all-players rule.

**Original cause (before the scoped repair):** native `effects.ts` records `revealCards` as a public log event, without a scoped visibility record. `projection.ts` grants the chooser access through modal `selectCards` options; it cannot distinguish a public reveal scope from private search/Foretell for another viewer. The adapter therefore cannot safely manufacture the missing public face. Parsing names from logs or exposing every modal candidate would leak hidden information.

**Proposed owner change, before production acceptance:** the Alpha Clash engine should own explicit revealed instance IDs, audience and lifetime tied to the native effect/Standby context. Projection should expose only those authorized faces to both seats while keeping private choice actions with the chooser. Clear or replace the scope on native completion, movement or relevant reorder, including rejection/undo/replay behavior. Preserve private Foretell/search and unrelated deck/hand identities. The existing visible-card projection can carry authorized faces; no shared gameplay protocol change is proposed here. If continuous reveal or nested scopes need additional presentation data, document that separately before changing the shared contract.

**Initial executable gap check (superseded by the repair below, 2026-10-10):** `destination-fixtures.test.ts` now has a named `test.fails` for the non-acting player’s public face. It asserts the intended equality against the actor’s native card definition; current null visibility is an expected failure, not passing reveal acceptance. The existing decline test now checks that both seats and the spectator have no visible deck identities before the trigger and after Done. Remove the expected-failure marker only with native scope support.

**Implementation boundary audit (2026-10-10):** `executeEffects` in the engine's `effects.ts` copies effect context for each instruction and stores remaining instructions in `PendingChoice.continuations`. `commands.ts` resumes both choice effects and those continuations. A visibility scope must survive these copies and nested choices; clearing it at the first nested return would hide a face too early. Conversely, storing it indefinitely on a card would leak the face after Done. `RuntimeCard.objectVersion` can identify moved objects, but `shuffleInPlace` and the `orderDeckCards` branch mutate deck order directly, so object version alone does not establish rule 703.8c invalidation. Scope cleanup must cover those native reorder paths as well. Instantaneous reveals without a suspended choice need a separate viewer-safe event payload for presentation; pending-choice metadata alone cannot cover them. This is an engine data/lifetime change, not a reason to parse public log strings or broaden shared choice visibility.

**Private-look guard:** the native test helper now exposes the pre-reveal Foretell stop, reusing the same attack, Shield response and payment path as the destination fixture. The regression verifies exactly two top cards for the chooser, no deck faces or private choices for the other seat/spectator, and unchanged state after a duplicate-card partition is rejected. These checks protect the private half of the same real-card chain while the public-face acceptance remains an explicit expected failure.

**Required acceptance:** native tests for both seats before/during/after Keep and Send; reordered/shuffled revealed card; nested/chained choices; no public face from private look/search; stale rejection leaves scope unchanged; replay reconstruction and local undo respect the native scope. Then repeat browser proof with both viewers, correct deck count, source/destination separation, no unauthorized intermediate texture and muted/reduced-motion variants. Do not mark `ac-reveal` native-complete from the existing public log alone.

### Suspended reveal repair — 2026-10-10

The engine now captures public card references in `revealCards` and carries them through the native effect context, newly created pending choices, and resumed modal/target/optional/number choices. Projection grants the public face independently of the chooser's private action data. A reference includes zone, object version and reveal version. Movement invalidates the old object reference; deck shuffling and `orderDeckCards` advance reveal versions, including a reorder that keeps the same top card. When the relevant choices and continuations complete, there is no remaining scope to grant visibility. No shared gameplay protocol field changed.

Internal effect-lifetime definitions are synthetic unit-test inputs, excluded from native visual coverage. Engine TypeScript check passes.

Reveal costs with Standby lifetime, instant reveals without a pending choice, replay/undo acceptance, broader reorder paths and browser opponent presentation remain follow-ups. A scope retained for an entire remaining effect can also be too broad if that card becomes irrelevant before a later unrelated choice; per-effect relevance remains an audit item. Do not mark the full reveal family complete.
